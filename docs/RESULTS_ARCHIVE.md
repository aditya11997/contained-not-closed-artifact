# Results archive: holdout hash manifest

This file lists every file of the holdout runs (`results/holdout/`), of the C1 Stripe conformance runs and of the dev runs (`results/dev/`), with its size in bytes and SHA-256. Use it to check the raw files wherever they are stored later: `shasum -a 256 <path>` must match the row.

The tables and totals are generated by script from the files on disk (`shasum -a 256` and `stat -f %z` over `find results/holdout results/conformance results/dev -type f`, macOS `.DS_Store` excluded). No value was typed by hand.

## Where the data is

- **In git:** the compact results. That is `trials.csv` (crash matrix: `crash_runs.csv`), `manifest.json`, `checker_summary.json`, `results/holdout/scaling/timing.csv`, the official conformance run, and everything in `paper/generated/` and `paper/figs/`. Rows marked "in git: yes".
- **Local only (untracked, `.gitignore`d):** the per-run data. That is `results/holdout/*/runs/*.tar.gz`, `checker_verdicts.jsonl` and the other `timing.csv` files. Rows marked "no (local)".
- **Dev runs (local only, `.gitignore`d):** all of `results/dev/`. These are exploratory, not evidence, and are listed in their own section. There is not enough disk space for a tarball now. These files will be archived externally later, and the archive location will be recorded here.
- `analysis.report` reads `checker_verdicts.jsonl` (verdict gating, PREREG §8), so `make results` needs the local files. The generated `paper/generated/*` and `paper/figs/*` were re-made from these files on 2026-10-24 and matched byte for byte.

## Reproducing the raw data

All five holdout runs ran on tag `prereg-v1` (commit `430c6a0279ffb97a7299dd23c210ffc102da1758`) with a clean tree. Each run's `manifest.json` records the commit, the argv, the seeds and the package versions. To regenerate, check out `prereg-v1` and run the commands in `docs/PREREG.md` §7:

```
python -m experiments.run --config configs/primary.toml          --partition holdout --out results/holdout/primary
python -m experiments.run --config configs/secondary.toml        --partition holdout --out results/holdout/secondary
python -m experiments.run --config configs/negative_control.toml --partition holdout --out results/holdout/negative_control
python -m experiments.run --config configs/scaling.toml          --partition holdout --out results/holdout/scaling
python -m experiments.crash_matrix --partition holdout --n-seeds 2000 --out results/holdout/crash_matrix
make results CONFORMANCE="results/conformance/stripe-20261024T024751Z"
python -m analysis.stripe_mapping results/conformance/stripe-20261024T024751Z --tex paper/generated/stripe.tex
```

The runs are deterministic for a given config and seed, and the per-cell `runs/*.tar.gz` are written with fixed mtimes and owners (`experiments/run.py`). `manifest.json` and `timing.csv` hold wall-clock times, so their hashes will differ on a rerun. The Stripe conformance run is a live test-mode run and cannot be reproduced byte for byte. Its files here are the record.
