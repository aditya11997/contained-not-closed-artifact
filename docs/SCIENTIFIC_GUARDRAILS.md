# Scientific validity and novelty check (mandatory)

## Research question
After perfect agent revocation, can a separately authorized, finality-aware disposition planner improve independently verified consequences over a competent incident-response runbook, holding remedy rights, status information, capacity and risk observations constant?

## The primary confound to avoid
If the candidate knows more, has more authority, gets better outcome queries, or has more remediation capacity than the baseline, superior results are not evidence of a new method. Run the comparison under identical information and permissions, with the same per-seed transaction timings.

## Baseline minimum
- No remediation (motivation only)
- Earliest-deadline-first (EDF)
- Value-per-time greedy
- Strong authorized operations runbook that queries current status, uses cancel-only authority, and treats unknown outcomes as unresolved
- Standard exact/approximate scheduling or compensation baseline if comparing algorithmic optimality; pure DP is not automatically novel

## Required claim discipline
- Current synthetic scheduling DP is established optimization, not an original scientific result.
- A 'kill switch' is an established control; contain versus operationally close remains a question to test, not a discovered gap.
- Do not claim payments are 'reversible' after capture unless rail-specific semantics support it. Current v0 defines capture as non-cancelable; refund/chargeback are different procedures and not implemented.
- No claim of payment-network-calibrated performance from synthetic merchant capture times.
- A successful cloud deployment improves experimental realism, not scientific novelty.
- Do not frame simulations as real incident data or infer actual patient or financial harm.
- State that payment mandates and merchant authorizations must be enforced outside the LLM.

## Novelty tests before writing
1. Compare to established post-incident runbooks, compensation/saga workflows, scheduling with deadlines, revocation and quiescence frameworks.
2. Test whether strong baseline equals candidate; report null results.
3. Demonstrate some additional property beyond classical scheduling, e.g. provable false-closure prevention under unknown status / authority partition, if true under stated assumptions.
4. Independent test checker separated from candidate code; oracle truth isolated from all candidate policies.
5. Blind holdout after hypotheses/metrics frozen; paired seed statistics, sensitivity analyses, negative results.
